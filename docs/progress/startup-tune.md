# Startup tuning (sensorless low-speed start): progress

Branch `ccr-5bff181d-bhhb1d`. A tool VESC Tool doesn't have: it runs sensorless FOC starts on the controller, measures each one with everything the firmware exposes, and searches the observer and open-loop settings that start the motor best.

Sources: `vedderb/bldc` master = 7.01 (`motor/mcpwm_foc.c` open-loop sequence and current controller, `motor/foc_math.c`, `motor/mc_interface.c` sampling, `comm/commands.c`, `lispBM/lispif_vesc_extensions.c` conf-set/conf-get/measurement extensions, `lispBM/README.md`, `lispBM/lispBM/doc/lbmref.md`) and the `release_6_05`, `release_6_06`, `release_7_00` branches for what older firmware has, read 2026-11-04.

## How it works

1. **Probe.** `core/vesc/src/main/resources/app/foctuner/vesc/tune/startup_probe.lisp`, streamed (`COMM_LISP_STREAM_CODE`, reset and load, never stored) after `LispCode.reduce`. It answers commands sent as `COMM_CUSTOM_APP_DATA` (`event-data-rx`) and replies with `send-data`. Commands: hello (selects motor 1 or 2), set and get parameters with `conf-set` / `conf-get` (RAM only), measure resistance (`conf-measure-res`), run a start, stop, quit. A start waits until the rotor has been still (≤ 4 s), disables app output for its length, drives `set-current` and samples every 4 ms: `get-rpm`, `get-rpm-faster`, `get-iq`, `get-id`, `get-iq-set`, `get-vd`, `get-vq`, `phase-observer`, `phase-motor`, `get-duty`, `get-est-lambda`, `get-est-res`, 26 bytes a sample, 8 samples a packet. It stops at the target speed, the time limit, a fault, a temperature or voltage limit, or a stop command, reports the end (outcome, reach time, fault, voltage, temperatures, estimates), brakes with half the start current below 150 ERPM and reports the release. Errors inside a start are trapped and release the motor.
2. **Side channels** (`StartupTuner`), alongside every start: realtime values (`COMM_GET_VALUES_SELECTIVE`, 5 Hz: temperatures, input voltage and current, fault, status) to stop at limits and report peak battery current; the observer angle stream (`COMM_SET_DETECT` observer mode, `COMM_ROTOR_POSITION`, 100 Hz); phase currents at switching rate for the first start of every candidate (`COMM_SAMPLE_PRINT`, start trigger, 500 samples spread over the open-loop sequence and the handover); the firmware's resistance measurement before the search; the `faults` terminal output after a fault.
3. **Analysis** (`StartupAnalysis`), per start:
   - open-loop sequences: the firmware overrides the FOC angle while its open-loop sequence runs (`m_phase_observer_override` in `mcpwm_foc.c`), so `phase-motor` differs from `phase-observer` (by about 45°: the observer is seeded 45° ahead). Count, duration, speed lost after the last handover, and the acceleration right after it relative to later (the torque the observer's angle still produced).
   - observer angle error: the back-EMF in the controller frame from the firmware's own dq model, e = v − R·i − jω·L·i (vd = R·id − ω·Lq·iq, vq = R·iq + ω·Ld·id + ω·λ, Lq/Ld = L ± ΔL/2), where it is readable (ω·λ ≥ 0.5 V and ≥ 2·R·|iq|): angle atan2(ed, eq), RMS and peak. During open loop the same back-EMF gives the rotor's speed against the open-loop speed (does the rotor follow the ramp).
   - flux linkage seen while running (|e| / ω and the observer's own estimate), backward travel, ripple of the fast speed estimate, q current tracking, duty peak; from the phase currents the peak over the start current, the spread of the current vector length and FOC angle jumps; from the rotor stream backward steps of the observer angle while the motor is slow (below 1500 ERPM, where 100 Hz can still tell direction).
4. **Cost** (`StartupCost`): time to the target over the starting settings' median, plus terms scaled so 1 means "noticeably bad": extra open-loop sequences, speed lost and torque lost at the handover, backward speed, ripple, angle error, open-loop slip, current peaks, observer reversals. A start that didn't reach the target costs 10 to 20 by how far it got, a fault 30.
5. **Search** (`StartupTuner`): starting settings, then one parameter at a time from the best so far: the measured resistance (if it differs by more than 8 % and the hardware has phase filters), the flux linkage the starts showed (if two sources agree), observer type (thorough, firmware 6.06+), observer gain ×0.5/0.7/1.4/2, open-loop ERPM ×0.6/0.8/1.25/1.6 (at most half the target), and with thorough lock, ramp and open-loop time. Three starts per candidate, alternating direction. A candidate replaces the best when it costs 3 % less. Then 3 (thorough 4) interleaved pairs of starting and best settings; the result is recommended only if it costs at least 10 % less and has no more failed starts. The starting values are set back in every case (`finally`, by the probe, or by writing the config as read), LispBM's stored code is started again if it was running, otherwise LispBM is paused.
6. **Tool** (Detection › Startup tuning): current settings, test settings (current, target, time limit, thorough, phase current recording), estimate of starts and minutes, confirmation, progress with the last start's speed (open-loop band) and current, findings, every candidate's score, Apply (stores the changes), Use until reboot (`conf-set` through a short-lived probe), Discard.

Defaults: start current a quarter of `l_current_max` (2..40 A); target twice the highest open-loop ERPM tried, at least 1500 and at most 40 % of the no-load speed at the pack voltage; 3 s per start, shortened to 2.5× the starting settings' slowest start once they all succeed. Limits: 5 °C below `l_temp_fet_start` / `l_temp_motor_start` (motor ignored without a sensor), 0.5 V above `l_battery_cut_start`. Refuses firmware before 6.05, non-FOC, sensor modes other than sensorless, undetected motors (R, L or λ zero), an active fault, a turning motor, low voltage, heat.

- `core:sim`: `StartupStartModel` (rotor dynamics, the firmware's open-loop sequencing, an observer whose lock speed, convergence, noise and bias follow gain, type, λ and R error; true motor 10 % more λ and 15 % more R than the config had when the probe started), `StartupProbeSim` (the probe's protocol on virtual time, conf-set into the stored config, set-current into the motor model so an emergency stop drops it, resistance measurement), `SamplingSim` records a probe start from its trace, `RotorPositionSim` streams the probe's observer angle, `LispSim.probeLoaded` / `generation`.
- `SimulatedVesc` fix: the reply loop waited with `withTimeoutOrNull` around a select; a reply taken at the instant the timeout fired was dropped (on a test clock replies and scheduled actions often coincide). The timeout is now an `onTimeout` clause of the select. Found because the tuner's 5 Hz poll lost a reply every few starts.
- App: `ui/tools/setup/StartupTuneTool.kt`, `strings_tune.xml`, `Tool.StartupTuning` in Detection (drives the motor, so demo mode pauses its ride).
- Tests: `StartupProbeScriptTest` (forms close; only LispBM 6.05 built-ins and the script's own functions are called, with the right arity; no locals that 6.05's loopwhile macro would shadow; the reduced script keeps every form; parameter order, sample layout, packet types, sizes and trial argument offsets match `ProbeCodec`), `StartupProbeCodecTest`, `StartupAnalysisTest` (angle error and flux linkage recovered from model voltages, inverted motors, open-loop runs, handover dip, rotor slip, phase current peaks and ripple, observer reversals, cost order), `StartupTunerTest` on the simulator (from a halved observer gain: the observer loses the motor, the resistance finding shows, the gain goes back up, verification accepts, every channel contributes, starting values back, motor released; stopping midway restores; a running script runs again afterwards; use until reboot; refusals; defaults), app `StartupTuneStateTest`. `./gradlew :core:vesc:test :core:sim:test :app:testDebugUnitTest :app:assembleDebug` green.

## Unverified

- Nothing has run on hardware. The probe script has never been evaluated by LispBM: the lint checks syntax, names, arity and layout, not semantics (number conversions in `bufset-*`, `spawn` with a stack size, `trap` results, events while a start runs).
- LispBM heap: the probe's code is about 1.6k cons cells (≈1.8k with bindings) of 2464 on 6.05 and about 2.7k on 7.01. The drive loop allocates boxed floats, so garbage collection will run often; the 4 ms period may stretch.
- `conf-set` of `foc-motor-r` / `foc-motor-flux-linkage` / the observer and open-loop parameters calls `mc_interface_set_configuration` while the motor is idle; assumed free of side effects.
- The angle error estimate assumes `get-vd` / `get-vq` are the applied voltages (they are the controller's output, so dead time and the voltage limit add error) and the firmware's sign conventions as read from `mcpwm_foc.c`. The cost uses its RMS, so a sign error wouldn't matter; a model error would show as a constant offset on every candidate.
- `COMM_MOTOR_ESTOP` should stop a start the probe drives (it makes `mc_interface` ignore input); not tested.
- Dual boards: motor 2 is picked when the selected CAN controller reports the attached board's UUID with the last byte + 1, and the rotor stream is skipped for it. Not tested.
- The simulator's start model is phenomenological: it reproduces the mechanisms (open-loop speed below the observer's lock speed, slip on a steep ramp, λ and R bias), not a particular motor's numbers. The end-to-end test proves the search and the plumbing, not the weights.
